## Method

- **Corpus**: `tests/eval/real_manifest.json` lists 38 openly licensed documents (source URL, licence, size, SHA-256): Wikimedia Commons PDFs and
  scans (public domain / CC0 / CC BY), Wikipedia articles as HTML (CC BY-SA 4.0), open-data CSV (ODC-PDDL), Wikidata JSON (CC0), Apache POI test
  documents (Apache-2.0). `tools/fetch_real_corpus.py` re-downloads and verifies hashes; no third-party file is committed (all are under 2 MB and git-ignored).
  Nine further cases are derived: every scan image also wrapped as an image-only PDF, and Russian DOCX/XLSX/PPTX/CSV built from the real text of a
  public-domain Russian government resolution (the corpus has no open-licensed Russian Office files, so those formats are Russian only in derived form).
  Nineteen adversarial synthetic cases (`adv_*`) are generated by the script.
- **Ground truth** is independent of the product: synthetic identities (Russian: ФИО, ИНН with valid checksum, phone, e-mail, passport, СНИЛС with
  checksum, Luhn card; English: name with middle initial, UK phone, e-mail, card, passport number) are injected into a copy of every document (text
  layer / header / table cell / new slide / rasterised banner for scans and images). Labels are the injected strings, not product output.
- **Recall** is end to end: an injected value counts as found only if it is no longer readable in the output when read by other tools (raw zip parts
  incl. nested zips, python-docx / openpyxl / python-pptx, PyMuPDF, poppler `pdftotext`, tesseract OCR of rendered pages at 200 dpi, and of images at 1x/2x),
  after folding zero-width characters, spacing/punctuation and Latin/Cyrillic look-alikes. PERSON counts as leaked when the surname is readable.
- **Precision** is only partly measurable: "TP" are replaced strings overlapping an injected value; "FP-unverified" are all other replacements. These are
  mostly legitimate detections of content already in the real document (officials in decrees, places, organisations, numbers) and are NOT counted as
  errors by this tool; read the column as over-redaction volume, not as a precision percentage. A manual review of sampled replacements found true false
  positives too (see eval-failures.md).
- **Restore fidelity**: original-with-injection vs restored output. Byte-equal for text/images; content-equal for Office (paragraph/cell/shape units)
  and PDF (multiset of words, since restored PDF fragments are re-laid out).
- **Time / memory**: wall time of `Service.anonymize` for one file, peak RSS of the whole worker process (one process per case, macOS, includes the vault and
  models, so about 110 MB is the floor).

## Limitations of this evaluation (read before trusting the numbers)

- Gold set is small per cell (1 value per category per document); percentages in single cells are coarse. Totals per format are 14 to 67 values.
- Injected blocks are short labelled lines ("Applicant: ...", "ИНН ..."). Real prose is harder for names; the numbers are an upper bound for names.
- English person names are the weakest point, so the language split mostly reflects English injected names, not English documents as such.
- OCR-based reading of outputs can miss a value an attacker with a better engine would read (false "no leak") and can misread (false leak is unlikely
  because values are matched exactly after folding).
- Fillable IRS forms were refused by the product as "signed" PDFs, so no leakage figure exists for them.
- No Microsoft Office / LibreOffice was available: "opens" means python-docx, openpyxl, python-pptx, PyMuPDF or Pillow can load the output, not that Word
  renders it unchanged. Visual layout fidelity was not measured.
- Large files (above 2 MB) were excluded from the corpus, so multi-hundred-page PDFs and big workbooks are covered only by the synthetic adversarial cases.
- Remote documents can change; a hash mismatch from the fetch script means the corpus drifted and results are not comparable.
