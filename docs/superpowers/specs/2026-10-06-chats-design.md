# Чаты: история работы, документы и редактируемые соответствия

Дата: 2026-10-06. Статус: черновик на согласование. Код не написан.

## Цель

Оформление как в Claude: слева список чатов, в центре лента шагов, справа таблица замен. Суть другая: **чат — это кейс**, набор файлов, которые идут вместе. В чате видны документы (исходный → обезличенный → возвращённый) и соответствия, и соответствия можно редактировать. Один и тот же интерфейс в окне программы и в панели Office.

Решения, согласованные с пользователем:

1. Визуал «как чаты в Claude», содержание — кейс с файлами.
2. Соответствия остаются в общем хранилище; чат показывает и правит только своё подмножество.
3. В чате по умолчанию хранятся обезличенная и возвращённая версии, зашифрованные ключом устройства. Исходный файл хранится только при явной галочке «Хранить оригиналы в этом чате».
4. Поля для вопросов модели нет: программа ничего не отправляет наружу. Внизу только область «перетащите файл».

## Что не меняется

- Хранилище (`vault.py`) остаётся одним на компьютер; метки глобальные (`Name1` везде один человек). Нумерация, формат метки, пометка файлов, резервная копия работают как раньше.
- Старые файлы, обезличенные до чатов, возвращаются без изменений.
- Распознавание, замена, проверки результата не затрагиваются.

## Модель данных

Новый модуль `anonymizer/chats.py`. Данные лежат отдельно от хранилища, в папке программы `chats/`, и шифруются тем же ключом устройства (`crypto.encrypt_blob`), как `Originals` в `addin.py`.

```
chats/
  index.bin                 зашифрованный JSON: список чатов (id, название, даты, число файлов)
  <chat_id>/
    chat.bin                зашифрованный JSON: шаги, файлы, использованные метки
    <file_id>.anon.bin      обезличенная версия
    <file_id>.restored.bin  возвращённая версия
    <file_id>.orig.bin      исходный файл (только если включена галочка)
```

Чат (`chat.bin`):

| Поле | Смысл |
|---|---|
| `id`, `title`, `created`, `updated` | название по умолчанию из имени первого файла (нейтральное, `Файл3`, если включено `neutral_names`) |
| `keep_originals` | галочка хранения исходников |
| `files[]` | `id`, `name`, `kind`, `status`, `tokens` (список использованных баз меток), `bytes` (какие версии лежат на диске) |
| `steps[]` | лента: `anonymize` / `restore` / `edit`, время, итог проверки, счётчики |
| `bound_doc` | привязка к документу Office (см. ниже), `null` для окна |

Таблица замен чата строится не копированием, а выборкой: для каждой базы из `files[].tokens` берутся сущность и написания из хранилища. Поэтому правка действует везде и расхождений между чатами нет.

### Правки в хранилище (реализовано, этап 1)

Формат не ломается: у сущности появляются необязательные поля `merged_into`, `vmap`, `edits`, у хранилища поле `pins`; старые копии читаются как раньше. Методы `Vault.merge`, `split`, `edit_value`, `forget`, `add_term`, `describe`; тесты `tests/test_vault_edits.py`.

- **Изменить значение.** Меняется текст написания у сущности: при возврате подставляется новое значение, во всех файлах. Метка не меняется.
- **Слить `NameA` в `NameB`** (это один человек). Пишется `aliases[NameA] = {to: NameB, variants: {1: k, ...}}`. Новые обезличивания выдают `NameB`. Старые файлы с `NameA` возвращаются дословно, как прежде, потому что `lookup` проходит через псевдоним и находит то же написание.
- **Разделить.** Одно из написаний выделяется в новую сущность с новым номером. Старые файлы с прежней меткой остаются верными для прежнего значения.
- **Не скрывать / всегда скрывать.** Запись в существующие `keep_terms` / `hide_terms`. Влияет на новые проходы.
- **Удалить сущность.** Помечается как удалённая (`removed`), возврат оставляет метку в файле и сообщает о ней, как сейчас для секретов.

Инвариант: правка никогда не делает так, чтобы ранее выданная метка начала означать другое значение. Слияние и разделение только добавляют правила.

## Применение правок к файлу

- Правка новых проходов (не скрывать, всегда скрывать, слияние) действует при следующем обезличивании.
- Чтобы пересобрать уже обезличенный файл чата, нужен исходник. Если он хранится (`keep_originals`), кнопка «Применить правки» делает повторный проход (`Service.rerun`). Если нет, программа так и говорит и просит добавить файл заново.

## API

Все маршруты под тем же токеном и проверками `Host`/`Origin`, что и остальные (`webapp.py`, `addin.py`). Имена файлов в журналы сервера не пишутся.

| Метод и путь | Назначение |
|---|---|
| `GET /api/chats` | список для боковой панели, группировка по дате на клиенте |
| `POST /api/chats` | новый чат |
| `GET /api/chats/<id>` | чат: файлы, шаги, таблица замен |
| `POST /api/chats/<id>` | переименовать, включить `keep_originals` |
| `DELETE /api/chats/<id>` | удалить чат и его документы (стирание файлов) |
| `POST /api/chats/<id>/anonymize`, `/restore` | задание внутри чата: результат записывается как шаг и версии файлов |
| `GET /api/chats/<id>/files/<fid>/<role>` | скачать версию (`anon`, `restored`, `orig`) |
| `POST /api/chats/<id>/entities/<base>` | правка: `edit` / `merge` / `split` / `keep` / `hide` / `delete` |
| `POST /api/chats/<id>/apply` | применить правки к файлам |

Существующие `/api/anonymize`, `/api/restore`, `/api/addin/*` остаются; без `chat_id` они работают как раньше и создают чат автоматически.

## Окно программы

Раскладка: слева панель (кнопка «Новый чат», список по датам «Сегодня», «Вчера», «Раньше», внизу настройки), по центру лента, справа выдвижная таблица «Замены». Внизу область «Перетащите файл или выберите».

Лента показывает шаги как сообщения: файл, результат («Обезличено, 14 замен» и кнопки «Сохранить как…», «Проверить»), вернувшийся файл, итог возврата.

Таблица замен: метка, вид, написания, «встречается в N файлах». Действия: изменить, объединить, разделить, не скрывать. Для слияния и удаления подтверждение.

Стиль остаётся прежним (тёплый фон, терракотовый акцент, засечки в заголовке, тема по системе). Требования к виду закреплены `PageContractTests`; боковая панель и таблица должны их соблюдать, а проверки обновляются осознанно, не обходом. Перед версткой применяются дизайн-скиллы по правилам проекта.

## Панель Office

Решение: **чаты живут только в приложении**, панель — клиент того же фонового процесса и своего хранилища не имеет.

- Панель работает с текущим документом: состояние («не обезличен», «обезличен, 14 замен», «возвращён») и кнопки «Обезличить», «Вернуть данные», «Откатить».
- Первое обезличивание в панели само заводит чат в приложении с названием документа. Повторное пополняет тот же чат.
- В панели короткий список замен только для просмотра. Правки (слияние, разделение, «не скрывать») делаются в приложении: кнопка «Открыть в приложении» открывает нужный чат (`/api/addin/open-app` уже есть).
- Зашифрованная копия оригинала для отката (`Originals`) привязывается к чату и живёт по его сроку хранения; отдельной галочки в Office нет.
- Привязка документа к чату: идентификатор чата записывается рядом с идентификатором хранилища в метаданных файла и переживает возврат и переименование. Запасной путь: чат с наибольшим пересечением меток. Сохранность идентификатора при пересохранении Office проверяется на реальном Word, Excel, PowerPoint.

## Жизненный цикл и безопасность

- Удаление чата стирает его документы и шаги. Общие метки в хранилище остаются, иначе сломаются другие чаты и ранее выданные файлы.
- Срок хранения: `retention_days` из настроек применяется к чатам тоже (по последнему обновлению). Возвращённые версии содержат реальные данные, поэтому у них отдельная настройка короче срока обезличенных, по умолчанию 30 дней.
- Исходники и возвращённые версии никогда не хранятся без шифрования. Предпросмотр реальных значений в таблице скрыт, пока пользователь не нажмёт «Показать».
- Очистка хранилища (`vault.clear`) удаляет и все чаты: новые номера меток делают их соответствия недействительными.
- Резервная копия: метаданные чатов входят, документы нет (по желанию отдельной галочкой).
- Вне зашифрованных файлов не появляется ничего: логи без имён, временные файлы чистятся.

## Миграция

Запись `history` из хранилища превращается в «архивные» чаты без файлов (только дата, тип и счётчики), по одному на задание, чтобы старый журнал не потерялся. Сами записи остаются в хранилище для обратной совместимости.

## Этапы

1. **Ядро:** `chats.py`, шифрованное хранение, `aliases` в хранилище, правки (изменить, слить, разделить), миграция. Тесты на инвариант «старые метки возвращаются» при любой правке.
2. **API:** маршруты чатов, привязка заданий к чату, удаление со стиранием.
3. **Окно:** боковая панель, лента, таблица замен. Проверка в живом окне на macOS (скриншоты, `tools/e2e_window.py` расширяется).
4. **Office:** панель на тех же API, привязка документа, проверка в Word, Excel, PowerPoint на macOS.
5. **Windows:** проверка WebView2 и Office на Windows нужна отдельно, на Mac она недоступна.

## Тесты

- Слияние и разделение: файл, обезличенный до правки, возвращается дословно после правки.
- Изменение значения действует во всех чатах и файлах.
- Удаление чата стирает файлы и не ломает метки в других чатах.
- Без `keep_originals` исходник на диск не попадает; «Применить правки» честно отказывает.
- Расшифровка чужим ключом отказывает, как для хранилища.
- Миграция старой копии хранилища без `aliases`.
- Обратная совместимость маршрутов без `chat_id`.
