# Desktop UI audit: keyboard operation, accessibility semantics, motion

Target: `anonymizer/web/index.html` (desktop window, not the Office dialog mode).
Date: 2026-10-07. Engine: real native pywebview window on macOS 26.6 (WKWebView, Safari-class WebKit 605.1.15).
Nothing under `anonymizer/` or `tests/` was edited. Throwaway drivers: `/tmp/aud/kb_audit.py` (subclass of `tools/shots_window.Shots`, same pattern as `tools/usability_window.py`), `/tmp/aud/contrast.py`; raw output `/tmp/aud/result.json`.

## What was and was not verified (read first)

- **A real screen reader pass (VoiceOver, NVDA, Narrator) was NOT performed.** Every statement about "what a screen reader says" below is inferred from DOM/ARIA attributes and known WebKit behaviour, not heard.
- `evaluate_js` cannot send trusted keystrokes. Tab order was **computed** (focusable elements in DOM order, filtered by `disabled`, `tabindex<0`, `inert`, `hidden`, `visibility`, `checkVisibility`, open modal dialog), not pressed. Enter/Space on rows are native `<button>` behaviour and were not synthesized. Escape in dialogs was emulated with `dialog.requestClose()` (fires `cancel`, as Escape does); Escape elsewhere and Ctrl/Cmd+B were dispatched as synthetic `KeyboardEvent`s on the focused element (the app listens on `document`, so this exercises the real handlers).
- **Focus ring rendering could not be seen.** Programmatic `focus()` does not match `:focus-visible` in this WebKit (computed `outline-style: none` after `.focus()`), so only the CSS rule and geometry were checked (see 8).
- **Motion:** tokens and running animations were read from computed style and `getAnimations()`. The window reported `document.hasFocus() === true`, but I did not visually confirm any transition frame by frame.
- `prefers-reduced-motion` could not be switched at OS level from here. Verified instead: the CSS rule exists, its effect was computed by injecting an unconditional copy, and the JS paths were run with `matchMedia` stubbed.
- Not exercised: Windows WebView2 (the shipped target), Office dialog mode (`ANON_DIALOG`), folder mode, merge and split end to end (the case file has no second code of the same kind and no multi-variant code; code read only).
- macOS note: with Full Keyboard Access off (default, `AppleKeyboardUIMode` unset on this Mac) WebKit Tab skips buttons and links and stops only on text fields. That is an OS setting the page cannot fix; keyboard-only users on macOS need Full Keyboard Access or Option+Tab. Windows WebView2 tabs through everything.

## P1

### P1-1. Destructive confirmations put initial focus on the destructive button
Evidence: `ask()` ends with `(typed ? input : choices ? pickBox : $("#ask-ok")).focus()`. Measured: delete chat dialog initial focus `button#ask-ok "Удалить чат"` (class `btn danger-main`); clear vault `button#ask-ok "Очистить"`; delete code `button#ask-ok "Удалить код"`. One Enter or Space deletes the chat or wipes the vault.
Fix: when `danger` is true focus `#ask-cancel` instead (keep `#ask-ok` second in DOM order, which it already is).

### P1-2. Focus is dropped to `<body>` after remove-file, run, and job completion
Evidence: removing a file with its "Убрать" button: `document.activeElement` becomes `BODY` (the list is rebuilt via `innerHTML`). Click "Обезличить" (focused): immediately `BODY` because `renderFiles` sets `disabled=true` on the focused button; still `BODY` after the result is rendered (`after_job_focus: BODY`). The result block is `aria-live` but not focusable, so a keyboard user restarts from the top of the document and has no way to jump to the result or the "Сохранить файл для ИИ…" button except by tabbing through the whole sidebar and feed.
Fix: (a) after removing a file focus the next "Убрать", else `#pick-chat`; (b) while running, do not disable the focused button (use `aria-disabled="true"` plus a guard in the click handler) or move focus to `#stage-chat`/the progress region with `tabindex="-1"`; (c) when the job finishes focus the result heading (`.status` gets `tabindex="-1"`, call `.focus({preventScroll:true})`, then the existing `scrollIntoView`). Also add `announce()` for "Файл добавлен" / "Обработка завершена".

### P1-3. Dialogs have no accessible name or description; validation errors are silent
Evidence: `#settings` and `#ask` have no `aria-labelledby`, `aria-label` or `aria-describedby` (measured `dlgName: null`, `describedby: null`). `#ask-error` has no `role`/`aria-live` (`role: null, live: null`) and the invalid input has no `aria-invalid` or `aria-describedby` (measured). Submitting an empty edit keeps focus in the input and shows "Значение не может быть пустым." visually only.
Fix: `<dialog aria-labelledby="ask-title" aria-describedby="ask-text">`, `<dialog id="settings" aria-labelledby="settings-title">`; `#ask-error` gets `role="alert"`; on error set `aria-invalid="true"` and `aria-describedby="ask-error"` on the input, remove on next input.

### P1-4. Escape in the chat-title field also closes the table pane (and the narrow sidebar)
Evidence: dispatching Escape on `#chat-title` with the pane open: `defaultPrevented === false`, afterwards `paneOpen === false`. The title's own `onkeydown` cancels the rename but does not stop the event, so the document-level handler (line ~1326) then closes the pane and moves focus to `#btn-table`. Escape in `#pane-search` also closes the pane and moves focus to `#btn-table` (intended, but same handler). On narrow windows the same bubbling would close the sidebar overlay.
Fix: in the title handler call `e.preventDefault()` (or `e.stopPropagation()`) on Escape; in the global handler return early for `INPUT/TEXTAREA/SELECT` targets unless explicitly wanted.

### P1-5. "Показать значения" has a changing label and `aria-pressed`
Evidence: initial `text "Показать значения", aria-pressed=false`; after click `text "Скрыть значения", aria-pressed=true`. A pressed toggle whose name flips announces as "Скрыть значения, toggle button, pressed" (inferred, not heard), which reads as contradictory on the one control that guards sensitive data.
Fix: keep one constant label ("Показывать значения") with `aria-pressed`, or keep the flipping label and drop `aria-pressed`. The `announce()` text is already good.

### P1-6. Repeated unlabeled action buttons in the feed and result
Evidence: tab order contains `button "Открыть"`, `button "Выгрузить файл…"` once per file version with no file or role in the accessible name (rows show the role as a sibling `<span>`). A buttons list in a screen reader would be "Открыть, Выгрузить файл…, Открыть, Выгрузить файл…". Names are fine elsewhere (`Убрать файл X`, `Изменить значение Company1`, etc.).
Fix: `aria-label="Открыть: ${shown}, ${ROLE_TEXT[r]}"` and `aria-label="Выгрузить файл: ${shown}, ${ROLE_TEXT[r]}"` (visible text is a prefix, so label-in-name holds).

## P2

1. **Tab order is correct but long.** DOM order equals visual order in every state (sidebar, header and title, feed, result, composer; pane last). No positive `tabindex`. The sticky composer's "Выбрать файл" sits after every feed button, so a chat with N steps needs about 4N Tab presses to reach it. Add a skip link ("К добавлению файла") or put the composer actions earlier. Verified lists: draft state 7 stops with sidebar open; with the sidebar collapsed the sidebar stops are removed (visibility hidden) and the first stop is `#btn-side-open`.
2. **Narrow overlay sidebar is not modal.** At 520 px the sidebar is a fixed overlay with a scrim, yet the main content is not inert (`main.inert === false`); Tab order still contains every background control after the sidebar. Escape closes the overlay and focus goes to `#btn-side-open` (verified). Fix: set `inert` on `.main` (and `#pane`) while the overlay is open on narrow screens.
3. **Sidebar shortcut (Ctrl/Cmd+B) works, with caveats.** Ctrl+B and Cmd+B both toggled from a focused chat item and from the title input; collapse moves focus to `#btn-side-open`, expand moves it to `#btn-side-close`; `aria-expanded` is `false/false` collapsed, hidden side `visibility: hidden` and absent from the tab order after the 240 ms delay. Issues: tooltip says "(Ctrl+B)" on macOS where the user expects ⌘B; the handler swallows Ctrl+B inside text fields (measured `defaultPrevented: true` on `#chat-title`; on macOS Ctrl+B is "caret left"); it is silent inside dialogs only. Fix: restrict to `Cmd` on macOS, `Ctrl` elsewhere, and skip when `e.target` is a text field or textarea.
4. **Heading structure is irregular.** Visible headings (chat open, pane open): `H1 Anonymizer` (inside the sidebar `aside`), `H3 Сегодня` (chat-list groups, under the H1, skipping H2), `H2 Замены`, `H3` code groups; empty state uses `H3`. The chat title is an `<input>`, so the main region has no heading. With the sidebar collapsed there is no visible H1 at all (measured 0). Fix: put a visually hidden `h1` in `<main>` (or make the title an h1 with a rename button), make chat groups `h2`, empty-state `h2`.
5. **`aria-controls` points at a missing id when a row is collapsed.** `.ent-row[aria-controls="more-Company1"]` with no such element (`ctrlExists: false`, true when expanded). Fix: always render an empty `#more-…` container, or omit `aria-controls` when collapsed. `aria-expanded` itself is correct (false then true after toggle) and the row is a real `<button>`.
6. **Masked values read as bullets.** The row accessible name is "Company1 •••••• 1 файл" and `.val.hidden` repeats `••••••` (inferred: many screen readers speak "bullet" six times). Fix: `<span aria-hidden="true">••••••</span><span class="sr-only">значение скрыто</span>`.
7. **Live regions are unreliable or double-announced (inferred, not heard).** `toast()` creates a `role="status"` node already containing its text, and `#flash`/`#pane-note` go from `hidden` (display none) to shown with the text set in the same tick; many screen readers skip such insertions. `showPaneNote()` both fills `#pane-note role="status"` and calls `announce()`, so the same text can be read twice. `#result-chat aria-live="polite"` is replaced wholesale, so the whole result block including buttons may be read. `#stage-chat role="status"` is rewritten on every 350 ms poll. Fix: keep one persistent polite region (`#sr-status`) as the single announcer; make the others silent (`role` removed or `aria-live="off"`), keep `#flash`/`#pane-note` as plain visible text, and announce only changes of stage text.
8. **Focus ring.** One global rule `:focus-visible { outline: 2px solid var(--focus); outline-offset: 2px }`; no `outline: none` anywhere in the file (grep: 1 hit). Colours: light 4.11:1 on bg, 3.85 on side, 4.26 on surface; dark 8.37, 8.86, 7.69 (all pass 3:1). Clipping check (focusables with 4 px ring against every `overflow` ancestor) returned none in draft, options-open, result, pane-open and settings states. Not visually confirmed (see top).
9. **Contrast (WCAG 2.2, computed from the OKLCH tokens, `/tmp/aud/contrast.py`).**
   - Pass 4.5:1: text 15.97/14.58 (light/dark); `--muted` on bg 5.74/7.23, on surface 5.94/6.64, on side 5.37/7.65, on hover 5.11/6.27, on select 4.81/5.50; accent 5.77/7.24; on-accent on accent 5.85/7.32; on-error on error 6.36/7.08; error on bg 6.27/6.74; toast 15.97/14.58.
   - **Fail 4.5:1 for real text:** placeholders and `--faint` text: light 2.98 on bg and 3.08 on surface; dark 3.85 on bg and 3.54 on surface (`input::placeholder`, `.chat-title::placeholder`). Fix: raise `--faint` to about oklch(0.55 0.01 255) light and oklch(0.66 0.008 250) dark, or use `--muted` for placeholders.
   - Disabled controls (`.btn:disabled` text 2.98/3.85, `.btn.main:disabled` on select 2.49/2.93) are exempt from WCAG contrast, but "Обезличить" disabled is the main call to action on the empty screen and is near-invisible in light theme; consider at least 3:1.
   - **Fail 3:1 for non-text boundaries:** text inputs, textarea, select and checkbox-less boxes are drawn with `--line-strong` borders: 1.62 (light) / 1.95 (dark) on bg, 1.67 / 1.79 on surface (`#chat-search`, `#pane-search`, settings textareas, selects, `.drop` frame). Buttons with text are exempt. Fix: darken `--line-strong` to about 3:1 for inputs only (new token `--field-border`).
   - Selected/pressed/expanded state is shown only by a tint: `--select` vs side 1.12 / 1.39, vs bg 1.19 / 1.31; hover 1.12 / 1.15. `aria-current="page"` exists for AT, but sighted keyboard users get almost no cue for "current chat" or "expanded row". Fix: add a non-colour marker (2 px inline-start inset marker is banned by the house rules, so use weight 600 on the title or a leading check/dot glyph).
   - Links in running text (`.link` in `.hint`, `.sub`, `.notice`): colour is `--muted` (same as the surrounding text) and the underline is `--line-strong` at 1 px, 1.62:1 / 1.95:1 against the background. Links inside sentences ("Что именно скрывается", "таблицу замен", "Закрыть" in notices) are therefore distinguishable only by a faint hairline. Fix: underline colour `currentColor` (or text colour `--text`) for `.link` inside `p`/`.hint`/`.sub`/`.notice`.
   - Status dots ok 5.45/8.76, warn 5.18/9.47 (and every status also has text). Progress fill vs track 4.68/5.51.
10. **Target sizes (measured `getBoundingClientRect`, all focusable controls in draft, options, result, pane, settings, narrow states; 46 unique).** No control is below 24×24 except the native checkbox glyphs (12×12), whose labels are full-row click targets (532×63, 470×21) so they pass in practice. Below 32 px high: `.link` buttons 18–19 px (`#open-settings` 19×69, "Открыть" 19×54, "Выгрузить файл…" 19×112, `#btn-result-table` 19×94, `#open-rules` 18×141, `#btn-pane-close` 21×56), `summary` rows 19–21 px, `#pref-retention` select 22 px, `#btn-reveal` 30 px. Pane row action links (`.acts`, `.ent-acts`, 12 px font, line-height 1.5) were not expanded during sampling; from CSS they are about 18 px high with only 4 px vertical gap, i.e. below the 24 px spacing exception on touch/pointer. Fix: `min-height: 24px` (ideally 32) with padding on `.link` and `summary`.
11. **Settings dialog discards edits silently.** Escape and backdrop click close it with no confirm; typing in "Всегда скрывать" then `requestClose()` closed with no warning (`dirtyWarned: false`) and the only button that saves is "Готово". Fix: Cancel button plus dirty check, or autosave on `change`.
12. **Toasts auto-dismiss in 4.5 s and carry errors** (save errors, "Идёт обработка файла. Дождитесь результата.", import/backup failures). No pause on hover or focus; a keyboard/SR user may miss them. Fix: keep error toasts until dismissed or move them into the visible `#flash`/inline error pattern.
13. **Pane opening shifts content for a frame.** Right after `#btn-table` click `#pane.scrollLeft === 31` (focus moved into `#pane-search` while the column is still 0 px wide and `overflow: hidden`); it settles to 0 after the 240 ms grid transition (measured 31 then 0). Fix: `focus({preventScroll:true})` and/or focus after `transitionend`; keep `scrollLeft = 0` on open.
14. **Lists lose semantics in WebKit/VoiceOver (known behaviour, inferred).** `ol#feed` and `ul#files-chat` have `list-style: none` and no `role="list"`; the chat-list, entity and var lists use the same pattern. Fix: add `role="list"` to each.

## What passed (verified unless marked)

- **Sidebar:** Ctrl+B and Cmd+B toggle; focus moves to the opposite toggle; `aria-expanded` updated on both toggle buttons; collapsed sidebar removed from tab order (`visibility: hidden`); `aria-label="Скрыть список чатов"` etc. Deleting a chat with the sidebar collapsed focuses `#btn-side-open`; with it open focuses `#btn-new-chat`. Escape closes the narrow overlay and focuses the open button.
- **Dialogs:** native `showModal()`: `:modal` matched, outside focus attempts ignored (`focus()` on `#btn-new-chat` left focus in the dialog), tab set limited to the dialog (edit: input, Отмена, Сохранить; delete code: Отмена, Удалить код). Settings opens with focus on the `h2` (tabindex -1) by design. After closing (cancel via `requestClose`): focus returns to the opener (`button#open-settings`; edit button "Изменить значение Company1"; `#btn-clear` after cancelling the nested confirm).
- **After delete chat:** focus goes to `#btn-new-chat` (`#btn-side-open` when collapsed), the opener being removed; the deletion is announced via `announce()` and `#flash`.
- **After table actions:** edit, undo, keep and forget all return focus to the row button via `focusRow()` (`button "Company1 •••••• 1 файл"`; after forget the row stays as "Значение удалено", so focus is not lost). Merge (no candidate pair, a toast appeared and focus stayed on the merge button) and split (no multi-variant row) were not exercised to completion.
- **Row toggle semantics:** `<button class="ent-row" aria-expanded>`; value toggles false→true. Action buttons carry `aria-label` that starts with the visible text (e.g. "Изменить значение Company1", "Удалить код Company1").
- **Closed pane:** `inert` plus `visibility: hidden` (measured), not in tab order; pane open: reveal, close, search, rows in order after the main content.
- **Progress bar:** `role="progressbar"` with `aria-label="Ход работы"`, `aria-valuemin/max/now`; now is updated each poll. Weakness: starts at 3 (a fake minimum), no `aria-valuetext`; the stage text is in a separate `role="status"`.
- **Motion tokens are applied** (computed): `.btn` transitions background/border/colour 0.12 s with `cubic-bezier(.25,1,.5,1)`; `#shell` grid-template-columns 0.24 s; `summary::before` 0.18 s; `.toast` animation `rise 0.18 s`; `#settings` `getAnimations()` shows `rise 180ms running` and `fade 180ms running` (backdrop). Sidebar and pane `visibility` use a 0.24 s delay on hide only. Nothing animates indefinitely and no property other than transform, opacity, colours, grid columns, max-width, width and height is animated (grid-template-columns and max-width are layout properties, acceptable for this shell).
- **Reduced motion:** `@media (prefers-reduced-motion: reduce)` sets all `animation-duration`/`transition-duration` to .01ms and delays to 0 (`!important`, on `*, ::before, ::after`). With the rule injected unconditionally: `.btn` 0.00001 s, `#shell` 0.00001 s, `#side`/`#pane` delay 0 s. JS paths with `matchMedia` stubbed to reduce: `<details>` open/close skips `animate()` and opens at once; `closeDialog_` closes synchronously. Whether the real OS setting is honoured by this WKWebView was not tested. Residual: the `.01ms` approach still plays one frame of the `rise` start state; acceptable.
- **Toast/flash/notice:** present with `role="status"` (see P2-7 for reliability).
- **Landmarks and language:** `<html lang="ru">`, `<main>`, `aside[aria-label=Чаты]` with `nav[aria-label="Список чатов"]`, `aside#pane[aria-label=Замены]`; `Убрать файл …` and `Название чата` have names; fieldsets have legends.

## Suggested fix order

1. P1-1 (cancel first on danger), P1-2 (focus after remove/run/done), P1-3 (dialog names, `role=alert`), P1-4 (Escape bubbling).
2. P1-5, P1-6 (cheap attribute changes).
3. Contrast tokens (`--faint`, `--line-strong` for fields, link underline) and `min-height` on `.link`/`summary`.
4. Live-region cleanup, heading structure, `inert` on the narrow overlay, `role="list"`, skip link.
5. Then a real VoiceOver (macOS) and NVDA/Narrator (Windows WebView2) pass with a physical keyboard; this audit cannot replace it.
