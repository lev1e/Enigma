## 1b. Product policy decisions (owner-approved, binding on all workers)

1. **Fail closed.** If the product cannot guarantee a result, it refuses or warns in plain language. It never returns a partly anonymized file marked OK.
2. **Images are replaced whole by default.** Detecting every logo, face, signature, stamp, handwriting, screenshot-of-screen or QR by detector is not guaranteeable, so for any image embedded in a document (docx/xlsx/pptx/pdf/html/md), and for standalone image files, the default is: replace the whole image with a placeholder (e.g. `Image1`), store the original encrypted in the vault, and put it back on restore. No face model is needed for this default. EXIF/XMP/ICC/thumbnail metadata is stripped from any image that is kept or output.
3. **Opt-in "redact text, keep image" mode** exists only for scans/screenshots the user wants an AI to read. It is best-effort: multi-pass OCR (scales 1x/2x/3x, rotations 0/90/180/270, two engines where available), pixel-destructive fill with the original stream dropped from the file, independent re-OCR verification; if any detector-matching value is still readable, or the page has handwriting, stamps, photos or QR that cannot be covered, the file is refused or the whole image is replaced, with a visible warning. The user must choose this mode explicitly; the UI says it is not a guarantee.
4. **Vault growth:** stored image originals count against a size limit and the existing retention/clear/backup rules; document the limit and what happens when it is hit (refuse, never silently drop).
5. **Formats:** every file type is either supported with measured quality, or refused with a one-line instruction. No silent pass-through. Unsupported today (per `service.py` UNSUPPORTED_HELP): `.xls .doc .ppt .rtf .odt .tif/.tiff .webp .heic`, password-protected, macro and signed files.
6. **Honesty:** wording is "reduces risk, verified on these corpora", never "guarantees". "Known limits" section goes into README/SECURITY.
7. **Network policy changes with the AI chat (W12) and must stay explicit.** Today the product sends nothing over the network (`SECURITY.md` says so; the only outbound code is the updater). The AI chat is OFF until the user adds a provider key in Settings. When on, the ONLY outbound content is text that has passed the anonymizer AND the outbound guard (below), sent only to the provider endpoint the user configured. No telemetry, no analytics, no third host. The UI shows a permanent "what leaves this computer" indicator and an outgoing log (labels only, no raw values). README/SECURITY are rewritten to say exactly this; the sentence "nothing is sent to the network" is replaced by the precise one, never left stale.
8. **Outbound guard (fail closed).** Before every request, scan the final payload (prompt, attachments, system prompt, file names, image data) against the vault: if any stored original value or any detector hit remains in clear text, block the send and tell the user which kind (not the value). Images are not sent unless replaced or redacted under policy 1b.2/1b.3. This guard is a release gate: outbound leak count must be 0 on every test corpus.

## 6. Where the ceiling is (stop rule)

Stop pushing a metric when two consecutive well-targeted fixes move it by less than the measurement noise, or when the remaining items need something rules cannot give (unknown names with no context, text visible only in images in the redact-text mode, very low-resolution scans). For image content the answer is the whole-image default (policy 1b.2), not a better detector. For each residual: add a fail-closed refusal or an "uncertain, ask the user" path, a plain-language warning in the UI/report, and an entry in a "known limits" section that goes into README/SECURITY. The ceiling, stated honestly: text entities in RU/EN in supported formats can reach zero leaks on the fixed corpora and a very low rate on unseen real documents; images are safe by replacement or refusal, not by detection; unsupported formats are refused; Windows OCR/Office behavior stays unverified until run on a real Windows machine. A product that is honest about its limits beats one that claims completeness.
