# Чаты: что сделано и что дальше (2026-10-06)

Спецификация: `docs/superpowers/specs/2026-10-06-chats-design.md`. Решения владельца: визуал как чаты в Claude, суть кейс; все чаты и редактирование только в приложении; add-in показывает состояние документа, а полный чат открывает всплывающим окном (`Office.context.ui.displayDialogAsync`) с той же страницей; исходники в чате хранятся только по галочке.

## Этап 2 готов (API и привязка заданий), закоммичено; полный прогон `run_tests.py`: 635 тестов, ОК

- `service.py`: `FileOutcome.tokens` (в `public()` не отдаётся). Для обезличивания метки собирает `TransformContext.file_tokens` (сбрасывается на каждый файл), а не дельта `ctx.tokens`: дельта отнесла бы общую метку только к первому файлу. Для возврата берётся `RestoreStats.entities`. `Job.chat`.
- `webapp.App`: `chats` (папка `chats` рядом с `vault.bin`, ключ хранилища), `purge` и `import_history` при создании, настройка `restored_retention_days` (30, в `DEFAULT_PREFS`), `clear_vault()` (хранилище и чаты; маршрут `/api/vault/clear` вызывает его), `apply_chat`, `materialize` (расшифрованная копия в `workdir/.open`), `cleanup_open` (при создании App и при выходе из `helper.run_helper`), `opener` (системная команда «открыть», в тестах подменяется).
- `start_job(..., chat_id, replace)`: после задания файлы и шаг пишутся в чат; без `chat_id` создаётся новый чат, название из имени обезличенного файла. Пока запись идёт, `job_public` показывает `running`, поэтому страница не увидит «готово» раньше чата. В ответе задания поле `chat`. Возврат внутри чата кладёт `restored` в запись с тем же именем обезличенного файла; если имя другое, берётся единственная запись, где есть все метки файла; иначе заводится новая запись. Повтор (`rerun`) заменяет записи прежнего задания. Неизвестный `chat_id` даёт 404 до запуска.
- `chat_api.py` (общий для окна и add-in): `GET/POST /api/chats`, `GET/POST/DELETE /api/chats/<id>`, `GET /api/chats/<id>/files/<fid>/<anon|restored|orig>`, `POST .../open`, `POST .../entities/<base>` (`action`: edit, merge, split, keep, hide, forget), `POST .../apply`. Правка пишет шаг `edit` без значений. Подключено в `webapp.Handler` (в том числе новый `do_DELETE`) и `addin.AddinHandler`. `/api/anonymize` и `/api/restore` принимают необязательный `chat_id`.
- Тесты: `tests/test_chat_tokens.py`, `tests/test_chat_app.py`, `tests/test_chat_routes.py` (окно по HTTP и add-in по HTTPS).

Не сделано и осознанно оставлено:
- Задания по папке (`/api/folder/*`) в чаты не пишутся.
- Add-in запускает задания своими маршрутами `/api/addin/*`; они записываются в новый чат при каждом обезличивании. Привязка документа к чату (`bound_doc`, повторное пополнение того же чата) относится к этапу 4.
- Страница add-in для диалога не получила `/api/upload`, `/api/anonymize`, `/api/jobs`: для полного чата в диалоге их надо отдать из `AddinHandler` (этап 4) или открывать диалог на странице окна.
- `import_backup` чаты не трогает.
