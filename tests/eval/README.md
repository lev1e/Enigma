# Evaluation datasets (versioned)

- `text_corpus_v1.jsonl` — 442 synthetic labelled sentences (spans + negative spans), generated by
  `tools/make_text_corpus.py`. Synthetic identities only. Measure with `tools/eval_text.py`.
- Document-level wrapping (docx/xlsx/pptx/pdf/txt/csv/html) of the same corpus: `tools/eval_docs.py`.
- Images: `tools/eval_images.py` (synthetic renders, independent re-OCR).

Bump the file suffix (`_v2`) when changing labels so metric history stays comparable.

## Results files and git worktrees

- `tools/eval_real.py run` writes `tests/eval/real/_results.json` (inside the git-ignored `real/` dir), never the tracked
  `tests/eval/real_results.json`. The tracked file is only the seed/reference: subset runs merge into it in memory.
  `eval_real.py publish` copies the working file over the tracked one (explicit, owner decision); `report` reads the working file, else the tracked one.
  `EVAL_RESULTS=<path>` overrides the working file (quality_gate uses a temp file).
- Worktrees: the raw corpus (~391 MB, git-ignored) lives in the main checkout. In a worktree create one symlink per entry
  under `tests/eval/real/` (`ln -s <main>/tests/eval/real/<entry> tests/eval/real/<entry>`); `real/.gitignore` ignores them. Do not symlink the
  `real/` directory itself (git would see it as a changed path). Alternatively `EVAL_REAL_DIR=<main>/tests/eval/real`.
  The per-checkout case dir `real/_cases` is recreated on every run; if it is a symlink (older setup) it is replaced by a real directory, not followed.

## CI jobs (`.github/workflows/quality-gate.yml`)

- `fast` (push to main, PRs, nightly): unit suite (`python -m unittest discover -t . -s tests -p "test_*.py"`) then `python tools/quality_gate.py`
  (text v1/v2/en + noise corpus vs `baseline.json`). Needs no corpus, no tesseract. pywebview/pythonnet are not installed on the runner:
  tests that need them must carry `tests/_guards.requires_pywebview` (see `docs/archive/superpowers-notes/requests-w6c.md`); OCR tests already skip via `ocr.available()`.
- `heavy` (nightly, or manual with `full=true`): `python tools/quality_gate.py --full --jobs 2`. Needs:
  - corpus: the untracked raw corpus at `$EVAL_REAL_DIR` (default `tests/eval/real`, 391 MB in the owner's main checkout). A GitHub runner has no copy, so the pinned real cases are reported as missing and the job fails by design until a corpus artifact/cache is provided;
  - tesseract with `rus` + `eng` data and poppler-utils (installed by the job); `tools/eval_real.py` also uses the macOS Arial font path for PDF injection (`FONT` constant), absent on ubuntu: set up a font or expect injection fallbacks;
  - time/memory: images + 16 pinned real cases with `--jobs 2`; a full `eval_real run` over ~300 cases is tens of minutes to hours; each worker peaks at roughly 0.2-1.5 GB (`peak_mb` in results), so keep `--jobs 2` on shared machines.
