# Безопасность

## Что программа делает и чего не делает

- Работает только на этом компьютере. Файлы, найденные значения и соответствия не отправляются в сеть. Телеметрии и отправки отчётов об ошибках нет. Единственные обращения в сеть: ИИ-чат (по желанию, ниже) и проверка обновлений собранной программы (`anonymizer/updater.py`): раз в 12 часов она читает ленту `latest.json` по HTTPS (адрес по умолчанию на GitHub Releases, переменная `ANONYMIZER_UPDATE_URL` его переопределяет). Данных пользователя в запросе нет (только `User-Agent` с версией); подпись Ed25519 ленты проверяется до любых действий. Отдельного выключателя проверки в `settings_schema.py` нет (не проверено, нет ли его в другом месте).
- Наружу уходит только то, что пользователь сам скачал и загрузил в стороннюю модель: обезличенный файл. Исключение: ИИ-чат (раздел ниже), выключенный по умолчанию.
- В обезличенный файл не попадают исходные значения. Секреты (пароли, ключи, токены, строки подключения) по умолчанию удаляются безвозвратно: в хранилище они не записываются. Исключение: пункт настроек «Сохранять пароли и ключи для возврата» (`retain_secrets_for_restore`, по умолчанию выключен); если его включить, секреты попадают в зашифрованное хранилище.

## Окно и локальный сервер

Окно показывает страницу, которую обслуживает локальный сервер на `127.0.0.1` (случайный порт). По умолчанию это сервер фоновой программы (`helper.py`), окно подключается к нему как клиент; в режиме `--inprocess` сервер работает в том же процессе. Браузер не запускается. Выбор и сохранение файлов идут через системные диалоги, а не через загрузки браузера: программа читает выбранный файл с диска сама и пишет результат в выбранное место.

- Доступ по ключу сеанса: окно открывает адрес с ключом, затем ключ хранится в cookie `HttpOnly; SameSite=Strict`. Запрос без ключа получает 403 и закрытое соединение.
- Проверяется заголовок `Host` (защита от DNS-rebinding) и служебный заголовок `X-Requested-With` у запросов, меняющих состояние.
- Заголовки `Cache-Control: no-store`, `X-Content-Type-Options`, `Referrer-Policy`, `Content-Security-Policy`: страница не загружает ничего внешнего. Политика разрешает `unsafe-eval`, потому что pywebview создаёт методы моста через `eval`; страница содержит только собственный код, все выводимые значения экранируются.
- Мост к системе (`js_api`) открывает только выбор файлов, сохранение результата, показ сохранённого файла в проводнике и резервную копию. «Показать в папке» работает только для файлов, которые записала сама программа.
- Одна копия на пользователя: вторая копия просит первую вывести окно вперёд по тому же ключу. Закрытие окна завершает процесс, временные файлы удаляются.
- Если на Windows нет WebView2 Runtime, программа сообщает об этом окном сообщения и завершается. Автоматического запасного пути через браузер нет.

## Хранилище соответствий

Один файл `vault.bin` в профиле пользователя (`%LOCALAPPDATA%\Anonymizer`). Содержимое — таблица «метка ↔ исходное значение», настройки и журнал заданий (имена обезличенных файлов и число замен).

- Шифрование: AES-256-GCM. Ключ устройства — 256 бит случайных данных; лежит в файле `device.key` в профиле. На Windows он защищён DPAPI и привязан к учётной записи, поэтому перенести хранилище на другой компьютер бесполезно. На macOS и Linux ключ хранится открыто в файле с правами `0600` (`crypto.load_device_key`): защита от других пользователей компьютера есть, привязки к учётной записи нет, а копия `device.key` вместе с `vault.bin` читается на другом компьютере.
- Без ключа устройства хранилище не читается, а программа не затирает нечитаемое хранилище.
- Срок хранения записей настраивается (по умолчанию 180 дней с последнего использования; возвращённые версии в чатах по умолчанию 30 дней, настройка `restored_retention_days`); в настройках есть полная очистка.
- Резервная копия шифруется паролем пользователя (scrypt + AES-GCM) и читается на любом компьютере. Хранить её нужно как секрет.
- В хранилище есть исходные значения. Оно защищает их от других пользователей компьютера и от копирования файла, но не от вредоносного кода, работающего под той же учётной записью.

## Временные файлы

Загруженные файлы и результаты лежат в папке `work` профиля. Все эти файлы содержат настоящие данные открытым текстом (возвращённые файлы тоже), поэтому они затираются нулями перед удалением и живут недолго:

- исходные копии (`in/`) удаляются, когда задание закончилось, а забытые после сбоя убираются через 10 минут;
- результат (`out/`), записанный в чат, удаляется через 30 минут после готовности; если человек уже скачал или сохранил все файлы, то через 10 минут после этого (запас на повторное «Сохранить»). Копия остаётся в чате, зашифрованная;
- результат, который в чат записать не удалось, остаётся до шести часов: другой копии нет, интерфейс об этом предупреждает;
- вся папка задания удаляется через шесть часов, а всё содержимое `work` — при выходе из фоновой программы;
- уборка запускается по таймеру (каждые две минуты) в работающей программе, а не только при старте; идущие задания она не трогает;
- временная папка окна (`anonymizer-window-*` в системной временной папке) затирается при закрытии окна, оставшиеся после сбоя старше 12 часов убираются при следующем запуске окна.

Файл `vault.bin.bak` (копия хранилища перед последним сохранением, зашифрована тем же ключом) удаляется и затирается после «Забыть значения» и «Очистить хранилище»: иначе в ней оставалось бы стёртое. Обычные правки копию не трогают.

Исходные файлы пользователя программа не изменяет: она получает копии.

## ИИ-чат (по желанию, выключен по умолчанию)

Это единственное место, где программа сама обращается в сеть, и только когда вы включили его.

- **Кто с кем говорит.** Страница `/ai` говорит только с локальным сервером (политика страницы `connect-src 'self'`, других адресов нет). К провайдеру обращается локальная программа: один POST на сообщение (плюс GET списка моделей при «Проверить подключение»). Повторов и пересылок нет. Редиректы не выполняются. Для чужих адресов нужен только `https`; `http` разрешён только для этого компьютера.
- **Что уходит.** Текст сообщения и последние сообщения беседы в виде меток (`Name1`, `Org2`), системная подсказка и заголовок с ключом API. Исходные значения и ключи хранилища не отправляются. Ключ идёт только в заголовке запроса, не в адресе и не в теле.
- **Три замка.** ИИ включён в настройках, ИИ включён для этого чата (по умолчанию выключен), исходящая проверка пропустила запрос. Проверка сверяет весь исходящий текст со всеми исходными значениями хранилища и запускает распознавание заново. Любая находка блокирует отправку. «Возможные» находки (`POSSIBLE_*`) тоже блокируют; для каждой можно выбрать «Обезличить» или «Разрешить один раз» (действует на одну отправку и нигде не запоминается). Точные находки (телефон, почта, секрет, значение из хранилища) разрешить нельзя, только скрыть. Если проверка не смогла завершиться, отправки нет.
- **Что видно до отправки.** «Показать запрос» выводит ровно тот адрес и тело, которые уйдут, ключа в них нет.
- **Хранение.** Беседа лежит в папке чата в зашифрованном ключом устройства файле `ai.bin`, только в виде меток. Возвращённый текст считается на лету для показа на экране, нигде не хранится и не попадает в следующие запросы. Удаление чата стирает файл, «Очистить хранилище» очищает и ключи ИИ.
- **Ключ API.** macOS: связка ключей через `security` (ключ передаётся через stdin). Windows: DPAPI, файл `ai_<id>.dpapi` в профиле (на реальном Windows не проверено); список провайдеров без ключей лежит в `ai_providers.bin`. Запасной путь: файл, зашифрованный ключом устройства (слабее, страница это показывает). Ключ не попадает в резервную копию, журналы, страницы и файлы чата. Страница получает только маску (последние 4 знака).
- **Журнал.** Остаются время, провайдер, модель, число знаков и список меток; текста сообщений и значений нет.
- **Исходные данные по выбору пользователя (P1).** В меню «+» у каждого файла чата можно выбрать версию, которая уходит модели: «Обезличенный» (по умолчанию) или «Исходный». Если выбран хотя бы один исходный файл, сообщение целиком считается сообщением с исходными данными: персональные данные не ищутся и не блокируют отправку, обезличивание и подстановка меток не выполняются, ответ показывается как есть (меток в нём нет, возвращать нечего). Перед отправкой в строке состояния один раз показывается «Отправляются исходные данные: провайдер (внутренняя/внешняя)», Enter подтверждает; подтверждение действует на ровно этот текст, провайдер, модель и выбор файлов. **Пароли, ключи, токены и строки подключения не уходят и в этом режиме:** распознанные значения заменяются на «[секрет удалён]», затем итоговый запрос проверяется ещё раз; если проверка не завершилась или что-то осталось, отправки нет. Распознаётся то же, что и в обычном режиме (слова «пароль», «password», «api_key», «token» со значением, Bearer, JWT, приватные ключи, строки подключения, адреса с паролем, ключи вида sk_live_...); произвольный ключ без такой подписи (например, голый `sk-proj-...`) этим распознаванием не находится. Сообщения, написанные в режиме исходных данных, помечены в беседе и никогда не попадают в историю обычного (обезличенного) запроса. Правка файла через ИИ в этом режиме не выполняется. В журнале исходящих запросов нет текста (время, тип и адрес провайдера, модель, число символов, режим).
- **Провайдеры и модели (P1).** Кроме Anthropic, OpenAI, Gemini и OpenRouter можно добавить любое число своих провайдеров: «свой адрес» с OpenAI-совместимым API (например, внутренняя «Тедорра» на Qwen): адрес, необязательный ключ, список моделей, галочка «внутренний сервер». Галочка только подпись: она задаёт метку «внутренняя»/«внешняя» и ничего не защищает. Выбор провайдера и модели лежит в поле сообщения (компактный список), запоминается для каждого чата и меняется в ходе беседы. Ключи хранятся как раньше.
- **Политика администратора (необязательна, P1).** Программа только читает файл `policy.json` (переменная `ANONYMIZER_POLICY`, иначе `%ProgramData%\Anonymizer\policy.json`, `/Library/Application Support/Anonymizer/policy.json` или `/etc/anonymizer/policy.json`). Файла нет: ограничений нет, любой провайдер и любая версия файла разрешены (решение владельца на этот этап). Если файл есть, он может задать уровень провайдера (`providers: [{id, tier, base_url}]`), `allow_originals_to_external` (false: исходные данные уходят только провайдерам уровня internal) и `allowed_hosts` (пустой список: без ограничения; иначе запросы к другим адресам не отправляются). Файл, который не читается или повреждён, трактуется в безопасную сторону: исходные данные не уходят. Файл читается при каждом запросе; программа его не создаёт и не меняет. Проверено на поддельном провайдере (tests/test_ws_p1.py); защиты от пользователя с правами записи в этот файл нет.
- **Add-in для Office** маршрутов ИИ не имеет.
- **Пределы.** У провайдера остаётся всё, что ушло в виде меток и окружающего текста: смысл, контекст, структура. Если распознавание пропустило значение, исходящая проверка видит его теми же средствами и может пропустить тоже. Провайдер может изменить или выдумать метки; повреждённые метки показываются отчётом, а не угадываются. Доступ к вашему компьютеру или к ключу ИИ даёт доступ к аккаунту провайдера. Проверено только на локальном поддельном провайдере; реальные провайдеры, реальная связка ключей macOS и DPAPI в этой сборке не проверялись. Правка файла по просьбе в строке сообщения чата сделана только для текстовых форматов (txt, md, csv, tsv, json, html, xml, log, yaml): ИИ получает текст файла с метками, ответ возвращается локально и сохраняется как новая версия файла, исходный файл и прежние версии остаются; при искажённых метках или без блока файла в ответе версия не создаётся. Для docx, xlsx и pptx правка идёт отдельным путём через JSON-патч (раздел ниже); для pdf правка в файл не переносится (программа говорит об этом и показывает текстовый ответ). Проверено только на локальном поддельном провайдере (tests/test_ws_s10a.py).

## Правка docx, xlsx и pptx через ИИ

- Что уходит провайдеру: текст сообщения и структура выбранной версии файла (адреса элементов, отпечатки, роли, тексты абзацев и ячеек; для просьб про оформление вместо текста идут заглушки). Названия макетов, стилей и шрифтов заменены номерами или опущены. Бинарного файла, метаданных и картинок нет.
- Версия: по умолчанию обезличенная (метки). По решению владельца ИИ может править и исходную версию (источник «исходный»): тогда текст идёт как есть, но пароли и ключи по-прежнему заменяются на «[секрет удалён]» (P1), а подтверждение отправки исходных данных остаётся. Если ИИ вернул эту маску в тексте правки, правка отклоняется.
- Ответ ИИ разбирается как один JSON-патч и проверяется локально на копии файла. Изменить можно только элементы, которые были в контексте; метки нельзя выдумывать; любая ошибка отклоняет весь патч («Файл остался прежним»). В файл ничего не пишется, пока пользователь не нажал «Применить».
- Применение создаёт НОВУЮ версию; исходный файл и прежние версии не меняются. Для обезличенной версии копия с настоящими значениями получается локальным восстановлением (неизвестная или повреждённая метка = версия не создаётся). Для исходной версии обезличенная копия делается обычным конвейером; если не получилось, пользователь видит явное предупреждение.
- Предложенные правки хранятся в зашифрованных данных чата (как сообщения), а не в открытом виде.
- Проверено только на поддельном провайдере и синтетических файлах; настоящий провайдер в тестах не использовался.

## Панель просмотра файла в чате

Справа от беседы можно открыть просмотр файла (вкладки «Обезличенный», «Исходный», «Возвращённый», версии).

- Просмотр строится на локальном сервере (`anonymizer/preview.py`) и отдаётся страницей как данные (JSON): страница собирает элементы через `textContent`, содержимое файла не становится разметкой и не исполняется. HTML, SVG и XML показываются исходным текстом. Разбор ограничен (8 МБ, 1500 строк, 100 строк и 24 столбца на лист, 12 листов, 400 блоков docx, 60 слайдов); всё, что не удалось разобрать или слишком велико, даёт отказ вместо показа.
- Подсветка меток включается только для обезличенных версий. «Исходный» и «Возвращённый» остаются локальными и помечены как содержащие настоящие данные; в ИИ и наружу они из панели не уходят.
- Файл markdown разбирается библиотекой marked и затем обязательно очищается DOMPurify (картинки, frames, формы, стили, svg, ссылки с адресами и атрибуты `href`, `src`, `srcset`, `target` запрещены; ссылки не кликаются). Подсветка кода (json, xml, yaml, ini, sql) работает по строкам и не меняет текст.
- Настоящие файлы PDF и Office в панели не открываются в браузере: страница получает только извлечённый текст, таблицы и слайды, а PDF и картинки идут как данные. Просмотрщики pdf.js, docx-preview и SheetJS в программу не входят.
- Ширина панели и состояние «открыта» хранятся в настройках страницы; текст файлов в них не попадает.

## Сторонние библиотеки в окне

В `anonymizer/web/vendor/` лежат три библиотеки: marked, DOMPurify и highlight.js (список, версии и хэши в `MANIFEST.json`, лицензии в `licenses/`, перечень в `THIRD_PARTY_NOTICES.md`). Они работают без сети. Файлы отдаются маршрутом `/vendor/<имя>` только по ключу сеанса, имя проверяется регулярным выражением, неизвестное имя даёт 404. Тест `tests/test_ws_s11c.py` и `tests/test_ws_s12c.py` сверяет хэши и падает, если в папке появился файл вне списка или файл из списка, который страница не подключает. Скачиваются файлы только при подготовке репозитория, программа сама ничего не скачивает.

## Известные пределы

- Изображения и сканы: по умолчанию (режим «заменять картинку целиком») каждая картинка в файле, включая вложенные в docx/xlsx/pptx/pdf/zip, заменяется заглушкой, а оригинал хранится зашифрованным в хранилище и возвращается при восстановлении; метаданные (EXIF, XMP, миниатюры) не сохраняются. В режиме «Закрасить текст, картинку оставить (менее безопасно)» картинка остаётся в файле, найденный распознаванием (OCR) текст закрашивается; OCR не гарантирует, что найдено всё, логотипы, лица и печати остаются видимыми. Если выбран этот режим (или он сохранён в настройках), программа показывает предупреждение в настройках и в результате каждого файла. Логотип, нарисованный в PDF векторно, а не картинкой, заменить нельзя: программа закрашивает только прочитанное название и предупреждает. Если надёжно обезличить картинку нельзя, файл не выдаётся.
- Автоматически найти можно то, что похоже на данные: незнакомые внутренние названия без юридической формы, кавычек и контекста программа может пропустить. Для этого есть список сомнительных слов и списки «Всегда скрывать».
- Метаданные документов (автор, организация) заменяются метками; нестандартные места вне XML (например, метаданные вложенных изображений) не проверяются.
- Метка `Name1` в тексте, который модель придумала сама, при совпадении номера с существующей записью будет восстановлена в чужое значение. Программа сообщает, если метки в файле относятся к другим ранее обезличенным файлам.
- Идентификатор хранилища записывается в свойства файла Office (`dc:identifier`) и PDF (`producer`). По нему при возврате отклоняется файл из другого хранилища. В текстовых файлах пометки нет; если модель пересохранила файл и пометка пропала, проверка не срабатывает.
- Ссылки на публичные сайты (поисковики, справочники, крупные компании) не заменяются, в том числе параметры запроса: имя в строке поиска останется.
- Вложенные файлы PDF и надстройки Office (think-cell и подобные) не обрабатываются.
- Нейросеть для имён (natasha, только русский, включена по умолчанию): работает на этом компьютере, в сеть ничего не отправляет. Она работает вместе с правилами: полные ФИО, найденные моделью с высокой уверенностью (около 97 % точности по замеру на тестовых текстах), заменяются сразу и запоминаются, так что все формы имени получают одну метку; правила и списки «не скрывать» имеют право вето; слабые находки правил внутри полного имени от модели подтверждаются. Остальное идёт в список проверки. Названия организаций и мест от модели не используются (объём лишних предложений в 4-8 раз выше допустимого). Слишком большой текст (больше 50 МБ) не разбирается моделью, об этом выводится заметка; в Markdown с разметкой разметка перед разбором гасится. Если модель недоступна, программа сообщает об этом и работает обычным поиском. Происхождение обучающих данных модели (новостные корпуса) не подтверждено: лицензия данных не проверена. На реальных документах заказчиков объём лишних предложений не измерялся.
- Не принимаются и отклоняются с инструкцией: .doc, .xls, .ppt, .rtf, .od* (конвертеры сознательно не включены; сохраните как .docx/.xlsx/.pptx), защищённые паролем файлы, файлы с макросами, PDF с цифровой подписью. Сканы, где после закраски остаётся читаемое значение, не выдаются (отказ вместо риска): так сейчас с четырьмя русскими сканами в режиме «закрасить текст».
- Страны и континенты скрываются как места (безопасное поведение по умолчанию); прилагательные вроде «российский» тоже.
- Название компании из одного обычного слова («Орбита»), опознанное явно (юридическая форма, кавычки), скрывается во всех падежах; без явного опознания однокоренные прилагательные не скрываются.

## Add-in для Office

- Страница панели отдаётся по HTTPS с `127.0.0.1:47831` (только петлевой адрес). Сертификат подписан локальным корневым сертификатом, ограниченным именами `localhost` и `127.0.0.1`; его ключи зашифрованы ключом устройства. Корневой сертификат ставится в доверенные для текущего пользователя.
- Каждый запрос проверяется: `Host`, `Origin` и `Sec-Fetch-Site` (чужие сайты отклоняются), заголовок `X-Requested-With` и токен установки (`X-Addin-Token`, сравнение через `hmac.compare_digest`); страница панели получает ключ в адресе (`pane_key`, HMAC от токена). CORS не включается: страница и API одного origin.
- Office.js скачивается при сборке (`tools/fetch_office_js.py`) и входит в установщик (лицензия Microsoft приложена): панель не обращается к сети и не отправляет телеметрию. В репозиторий файлы Microsoft не входят.
- Копии документов до замены хранятся зашифрованными (AES-256-GCM, ключ устройства), не дольше 7 дней и не более 20 штук.
- Office сам записывает имя пользователя в свойства файла при сохранении и в части версий не даёт их изменить: панель предупреждает об этом после замены.

## Окно и фоновая программа

Окно получает доступ к фоновой программе по токену из `instance.json` (профиль пользователя, как и ключ устройства). Пути файлов окно отправляет в `/api/native/upload-path` и `/api/native/folder`: эти маршруты есть только на сервере страницы программы и недоступны с HTTPS-сервера add-in.
